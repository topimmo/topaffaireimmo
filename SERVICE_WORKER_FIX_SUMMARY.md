# Service Worker Registration Fix - Summary

## Problem Statement

**Production Error (Sentry):**
```
TypeError: Failed to register a ServiceWorker for scope (...) with script (/sw.js): 
ServiceWorker script evaluation failed
```

This error was occurring in production on Vercel, but not locally.

## Root Cause Analysis

The Service Worker registration was attempting to register on domains where it shouldn't be active:

1. **Vercel Preview URLs**: `*.vercel.app` domains where the app is deployed for preview
2. **Build Artifact Location**: The `/sw.js` file is generated by Vite PWA at build time to `/dist/sw.js`, not `/public/sw.js`
3. **Insufficient Guards**: While the code had bot detection and environment checks, the production domain validation was not strict enough

### Why It Failed

- On Vercel preview URLs, the SW attempted to register even though the app shouldn't have a SW on preview environments
- The hostname check used a configurable `VITE_PRODUCTION_DOMAIN` variable, which might not have been set correctly
- The check allowed multiple domains (`topaffaireimmo.com`, `www.topaffaireimmo.com`) which could cause confusion
- No cleanup mechanism if registration failed

## Solution Implemented

### 1. Stricter Production Environment Check

**Before:**
```typescript
// Must be in production mode
return import.meta.env.PROD;
```

**After:**
```typescript
// Must be in production mode (NODE_ENV === 'production')
if (!import.meta.env.PROD) {
  return false;
}
// ... additional hostname checks ...
return true;
```

The check now happens EARLY and EXPLICITLY, ensuring we're in production mode before any hostname validation.

### 2. Hardcoded Production Domain

**Before:**
```typescript
const productionDomain = import.meta.env.VITE_PRODUCTION_DOMAIN || 'topaffaireimmo.com';
const allowedHosts = [
  productionDomain,
  `www.${productionDomain}`,
  'localhost',
  '127.0.0.1'
];
```

**After:**
```typescript
const isLocalhost = currentHost === 'localhost' || currentHost === '127.0.0.1';
const isProductionDomain = currentHost === 'www.topaffaireimmo.com';

if (!isProductionDomain && !isLocalhost) {
  console.log(`[SW] Skipped: hostname "${currentHost}" not allowed (production requires www.topaffaireimmo.com)`);
  return false;
}
```

**Benefits:**
- Explicit, hardcoded production domain (no environment variable confusion)
- Clear separation between localhost (for testing) and production
- Informative log messages explaining why registration was skipped

### 3. Fail-Safe Unregistration

**Added:**
```typescript
catch (error) {
  console.warn('[SW] Registration failed (this is normal for some environments):', error);
  
  // Attempt to unregister any existing service workers on failure
  try {
    await unregisterServiceWorker();
  } catch (unregisterError) {
    console.debug('[SW] Unregistration also failed (expected if no SW exists)');
  }
  
  return false; // Don't rethrow
}
```

**Benefits:**
- Cleans up any stale service worker registrations
- Ensures the app returns to a clean state if SW registration fails
- Prevents partial/broken SW states

### 4. Silent Error Handling for Sentry

**Key Changes:**
- Errors are caught and logged with `console.warn` (not thrown)
- Unregistration errors use `console.debug` to reduce noise
- Function returns `false` on failure instead of throwing

**Benefits:**
- Sentry won't capture these errors as they're expected in some environments
- Console remains clean for developers
- App continues to function without SW if registration fails
