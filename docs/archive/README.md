# Archived Documentation

This folder contains historical documentation from previous fixes and iterations.
These files are kept for reference but are not part of the current setup process.

**Last Updated**: 2026-02-06 - Major cleanup moved 120+ root-level markdown files here.

## What's Here

This archive contains historical documentation including:

- **Implementation Summaries**: Documentation of features, fixes, and changes implemented over time
- **Diagnostic Reports**: Technical investigations and diagnostic findings
- **Testing Guides**: Historical testing procedures and checklists
- **Fix Summaries**: Documentation of specific bugs and their resolutions
- **PR Descriptions**: Pull request descriptions and summaries
- **Migration Notes**: Database migration documentation
- **Deployment Guides**: Historical deployment procedures

## Categories

Files are organized by topic prefix:

### Admin & Authentication (`ADMIN_*`, `AUTH_*`)
- Admin dashboard implementation and structure
- Authentication fixes and flows
- Admin whitelist and authorization
- Profile management

### Deployment & Production (`DEPLOYMENT_*`, `PRODUCTION_*`)
- Multiple deployment guide versions

- Production readiness checklists and diagnostics

### Database & Migrations (`FK_*`, `RLS_*`, `MIGRATION_*`)
- Foreign key constraint fixes
- Row Level Security policies

- Schema refactoring notes

### Features (`FEATURED_*`, `PROMO_*`, `PUSH_*`, `PWA_*`, `SEO_*`)
- Facebook integration implementation
- Featured properties and promo banners
- Push notifications implementation
- Progressive Web App (PWA) setup
- SEO enhancements and optimization

### Diagnostics & Fixes (`DIAGNOSTIC_*`, `FIX_*`, `*_FIX_SUMMARY.md`)
- Comprehensive diagnostic reports
- Bug fix summaries and documentation
- Root cause analyses
- Troubleshooting guides

### Testing & Validation (`TESTING_*`, `VALIDATION_*`, `VERIFICATION_*`)
- Testing guides and checklists
- Validation reports
- Phone validation testing
- Property workflow testing

## Why Archived?

These documents were moved from the root directory to:
- Improve repository organization
- Keep the root clean and focused on current documentation
- Preserve historical context and implementation details
- Make it easier to find active vs. historical documentation
- Reduce clutter while maintaining project history
